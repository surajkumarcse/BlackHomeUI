How this Android launcher works

Three questions, answered from this project's actual manifest and Kotlin code. Learn how Android recognizes the home app, follow the runtime flow, and find the first activity callback to read.

The short version: MAIN + HOME + DEFAULT makes MainActivity eligible as a home screen. For a newly created activity, your UI setup begins in MainActivity.onCreate(), which installs a Compose UI rooted at MinimalLauncher().

QUESTION 01

How is it identified as a UI launcher?

Android does not decide this from the project name, the black background, or the appearance of the UI. It matches the activity's intent filters in AndroidManifest.xml against the action it needs to perform.[1]

Home-screen eligibility

This is the filter that makes the activity a home-app candidate:

<intent-filter>
    <action android:name="android.intent.action.MAIN" />
    <category android:name="android.intent.category.HOME" />
    <category android:name="android.intent.category.DEFAULT" />
</intent-filter>

MAIN is the main entry action; HOME identifies a home-screen handler; DEFAULT allows matching for normal implicit activity launches. It does not mean this app has already been chosen as the device's default.[2]

Ordinary app-drawer entry

A separate filter lets the app appear in an existing launcher's app list:

<intent-filter>
    <action android:name="android.intent.action.MAIN" />
    <category android:name="android.intent.category.LAUNCHER" />
</intent-filter>

LAUNCHER means "show this activity as an app that can be opened." Many ordinary apps have this filter. It does not by itself make an app a replacement home screen.[2]

Eligible is not the same as selected. The manifest declares a home-app candidate. Android's default-home selection determines which candidate handles Home. This code does not automatically replace your existing default launcher.[3]

Both filters are inside the same activity declaration:

<activity
    android:name=".MainActivity"
    android:exported="true"
    ... >

In this project, .MainActivity refers to com.lostfalcon.myminimalistdesignhomepage.MainActivity. exported="true" permits external launch requests; it is not the home-screen identifier. The filters determine which intents the activity advertises handling.[1]

Do not confuse the two uses of LAUNCHER in this manifest. The MAIN + LAUNCHER signature under <queries> describes other apps this app wants visibility into. Only the filters inside <activity> advertise this activity's entry points.[4]

What actually supplies the launcher UI?

MinimalLauncher() builds a two-page HorizontalPager: HomeScreen() for the clock, favorites, phone, and camera; AppsScreen() for the searchable app drawer. loadLaunchableApps() uses Android's LauncherApps service to enumerate launchable activities in available profiles.[5]

QUESTION 03

What code is executed first here?

Start reading at MainActivity.onCreate(). It is the first lifecycle callback overridden by this project's activity, and the entry point for its UI setup on a new activity instance. The override begins at line 95.
app/src/main/java/com/lostfalcon/myminimalistdesignhomepage/MainActivity.kt 
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            MyMinimalistDesignHomePageTheme {
                MinimalLauncher()
            }
        }
    }
}
Read this call chain from top to bottom for the activity's UI initialization.
OrderCodePurpose here
1onCreate(savedInstanceState)Android invokes the callback for a newly created MainActivity.
2super.onCreate(savedInstanceState)The first statement in this override delegates to ComponentActivity's initialization.
3enableEdgeToEdge()Configures edge-to-edge drawing; the screens use system-bar padding for their content.
4setContent { ... }Installs the Compose content rather than inflating an XML layout.
5MyMinimalistDesignHomePageThemeWraps the content in MaterialTheme with this project's dark colors and typography.
6MinimalLauncher()Owns launcher state, preferences, lifecycle refresh, pager, and dialogs.
7HomeScreen() / AppsScreen()Describe the UI for pager pages; Compose renders and updates them as needed.
Important precision: onCreate is not the literal first code in the process. Android framework startup, dependency initializers/providers, Application initialization, and activity construction can occur before this callback. This source manifest declares no custom Application class. There is no app-authored main() function that you call to launch this UI. On returning to an existing activity, onCreate() need not run again.[7]
